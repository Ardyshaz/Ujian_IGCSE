# Audit UI UX workflow dan engine ujian

Tarikh: 18 November 2026, waktu Malaysia. Baseline aplikasi: commit `1b0585a`, https://kuiz-igcse.web.app.

Status: laporan disimpan untuk disambung kemudian. Dapatan di bawah belum dilaksanakan. Laporan ini ialah backlog cadangan dan tidak menggantikan `full_prompt.md`, mengubah keputusan produk atau mengesahkan format peperiksaan rasmi.

## Rumusan

Aplikasi mempunyai asas yang baik untuk latihan komuniti: profil keluarga, pemilihan soalan berdasarkan sejarah, pemarkahan jawapan pertama, rekod cubaan immutable, penghantaran dengan retry, PDF/JSON, glosari, panduan dan pencapaian mingguan sudah tersedia. Keutamaan seterusnya ialah kebolehpercayaan simpanan dan penghantaran kuiz, kejelasan pengalaman pelajar, kedalaman bank soalan serta pemulihan data. Tambahan kosmetik boleh menyusul selepas isu tersebut.

## Skop dan bukti

- Semakan kod meliputi shell/router, Home, tetapan kuiz, sesi/pemasa, semakan dan keputusan, Dashboard, Bank Soalan, panduan/glosari, profil, repository Firestore, eksport, maklum balas, sokongan, Analytics, Hall dan counter.
- `npm test`: 39/39 unit tests lulus.
- `npm run test:rules`: lima suite lulus, dengan 137 semakan eksplisit: 31 pemilikan/markah, 23 maklum balas, 39 Hall/profil legasi, 20 Hall automatik dan 24 counter. Terdapat juga assertion nilai active/total.
- `npm run check:content`: 300 soalan, 100 setiap subjek, 62 topik; semakan struktur lulus.
- `npm run check:docs`: pautan/case dalam 49 dokumen Markdown semasa lulus. Ini tidak membuktikan semua ayat dokumentasi atau UI sudah terkini.
- Reproduksi engine tambahan dijalankan dalam memori menggunakan kod API dan bank sebenar, dengan repository/storage/network tiruan. Tiada panggilan Firebase atau perubahan rekod pelajar sebenar.
- Audit visual baharu tidak dijalankan: browser host tidak tersedia. Semakan kelulusan automatik menolak akses kepada Chrome sedia ada kerana tetingkap itu mengandungi sesi GitHub/peribadi di luar skop aplikasi. Permintaan izin tab khusus dihantar; tiada kebenaran baharu diterima semasa laporan ini disimpan. Jangan anggap permintaan tertangguh sebagai izin.
- Bukti browser release terdahulu direkodkan dalam [validation history](VALIDATION.md). Ia bukan bukti audit visual baharu dan bukan ujian Android/iOS fizikal.

Semua dapatan perlu dibezakan antara tingkah laku engine yang direproduksi, kesimpulan daripada kod dan cadangan produk yang masih memerlukan penilaian pengguna/peranti.

## Dapatan keutamaan tinggi dan sederhana

### A01 Jawapan ditaip belum autosave semasa menaip

Keutamaan: tinggi. Bukti: kod; belum diuji secara visual dalam audit ini.

`typed-answer` disimpan melalui event `change`, bukan event `input`. Jika masa tamat atau halaman dimuat semula ketika medan masih fokus, teks terakhir mungkin belum masuk ke draf. `beforeunload` hanya mengesan `pendingSaves`, bukan teks yang belum pernah dimasukkan ke queue.

Cadangan: autosave pada input dengan debounce pendek, status simpanan yang jelas dan pengendalian storage error. Jangan menganggap teks yang kelihatan dalam input sudah tersimpan.

Penerimaan: taip tanpa blur, refresh dan sambung semula; jawapan dipulihkan. Uji taip berhampiran deadline, komposisi input, storage penuh dan navigation pantas. Kekalkan pemarkahan jawapan pertama serta retry attempt ID asal.

Rujukan: [app.js](../../public/js/app.js), fungsi `queueSave`, listener `change`/`input` dan `beforeunload`.

### A02 Simpanan tertangguh ketika deadline boleh menyekat penghantaran

Keutamaan: tinggi. Bukti: engine direproduksi dan laluan panggilan disemak.

API menolak PATCH jawapan selepas deadline. `finish()` pula menjalankan `flushSave()` sebelum submit. Jika jawapan masih berada dalam queue apabila deadline berlalu, flush boleh terus gagal dan menghalang submit. Reproduksi memori menghasilkan `Masa telah tamat. Hantar jawapan yang sudah disimpan.`; submit terus tanpa perubahan lewat menghasilkan satu soalan belum dijawab.

Cadangan: tetapkan peraturan jelas bagi jawapan yang direkodkan sebelum deadline dan perubahan selepasnya. Bekukan jawapan sah, elakkan satu pending update yang tidak lagi layak menyekat keseluruhan penghantaran, dan beri penjelasan kepada pelajar. Ini masih pemasa latihan client-side, bukan pemasa peperiksaan yang dipercayai.

Penerimaan: jawapan sebelum deadline dipelihara mengikut peraturan yang diputuskan; perubahan selepas deadline tidak diterima secara senyap; auto-submit dan retry akhirnya boleh menyimpan satu attempt sahaja. Uji juga offline/reconnect selepas tamat masa.

Rujukan: [app.js](../../public/js/app.js), `flushSave`, `updateTimer`, `finish`; [api.js](../../public/js/api.js), deadline guard dan submit.

### A03 Semua route bergantung pada Dashboard cloud

Keutamaan: tinggi. Bukti: kod dan simulasi kegagalan repository.

`renderRoute()` memuatkan `/dashboard/{studentId}` dahulu untuk setiap route apabila profil dipilih. Dashboard mengambil semua attempts daripada server. Kegagalan itu membawa kepada error page sebelum panduan, Bank Soalan atau draf tempatan dirender. Draf disimpan secara tempatan tetapi pembukaannya masih bergantung pada panggilan cloud tersebut.

Cadangan: asingkan data wajib setiap route. Kandungan tempatan dan draf sedia ada perlu mempunyai laluan pemulihan yang tidak menunggu statistik. Bezakan ciri membaca/menyambung draf daripada penghantaran cloud yang memerlukan acknowledgement. Jangan menjanjikan full offline/PWA tanpa melaksanakannya.

Penerimaan: selepas profil dikenal pasti, kegagalan fetch attempts tidak menyekat panduan/Bank Soalan; draf boleh dibaca semula mengikut sokongan offline yang ditetapkan; penghantaran tetap menunjukkan status belum disahkan jika cloud tidak tersedia.

### A04 Skip link bercanggah dengan hash router

Keutamaan: tinggi untuk aksesibiliti. Bukti: kod; pengesahan keyboard/browser masih diperlukan.

`index.html` menggunakan `href="#main"` untuk Langkau ke kandungan. Listener `hashchange` menyerahkan semua hash kepada router, yang tidak mempunyai route `main`. Pautan aksesibiliti ini boleh menghasilkan halaman tidak ditemui.

Cadangan: urus skip action sebagai perpindahan fokus ke kandungan, bukan pertukaran route. Semak juga fokus heading selepas navigation biasa.

Penerimaan: Tab pertama mencapai skip link; Enter memfokuskan main tanpa menukar halaman atau memadam konteks kuiz. Uji dengan keyboard dan screen reader.

### A05 Jumlah tersedia Challenge tidak sepadan dengan pemilihan

Keutamaan: sederhana. Bukti: engine direproduksi.

Paparan jumlah soalan menggunakan penapis umum, manakala Challenge tanpa Level khusus menambah syarat Level >=3. Contoh: topik Grammar diiklankan mempunyai 6 soalan, tetapi permintaan Challenge bagi jumlah itu ditolak: `Hanya 3 soalan sepadan. Kurangkan bilangan soalan.`

Cadangan: gunakan satu fungsi penapis bagi kiraan tersedia dan pemilihan sebenar. Laraskan had input dan mesej sebelum pengguna menekan Mula.

Penerimaan: jumlah yang dipaparkan tepat bagi setiap mod/topik/Level; pengguna tidak ditawarkan jumlah yang tidak dapat dipenuhi. Kekalkan penapis eksplisit pengguna.

### A06 Status dijawab tidak dikemas kini serta-merta

Keutamaan: sederhana. Bukti: kod; pengesahan visual masih diperlukan.

Handler pilihan jawapan mengubah gaya pilihan dan menyimpan jawapan tetapi tidak terus merender semula kiraan dijawab, progress bar atau class `answered` pada nombor navigasi. Ia dikira semula dalam `renderQuestion()`. Pelajar boleh melihat pilihan sudah dipilih sedangkan petunjuk lain masih tertinggal sehingga berpindah soalan.

Cadangan: kemas kini semua petunjuk secara konsisten selepas simpanan. Kekalkan gold flag automatik apabila Semak jawapan ditekan dan jangan kembalikan checkbox lama.

Penerimaan: pilih/taip jawapan dan lihat kiraan, bar serta navigasi berubah tanpa perlu Next/Back. Keadaan kosong mesti dilabel belum dijawab secara konsisten pada visual dan aria-label.

### A07 Teks UI lama bercanggah dengan aplikasi live

Keutamaan: sederhana. Bukti: kandungan semasa.

- Tentang Projek masih menyebut tiada leaderboard awam, penggunaan localhost dan belum ada deployment awam.
- Tips Home masih mempunyai pautan glosari 100 istilah; koleksi semasa ialah180.
- Bank Soalan masih menggunakan label `Practise`; pertimbangkan `Latih soalan ini` untuk konsistensi BM.

Cadangan: semak keseluruhan copy terhadap keadaan sebenar, termasuk storage cloud, alias awam, operasi hosting dan batasan pemulihan. Gunakan nilai dinamik bagi bilangan istilah. Kekalkan tepat disclaimer dan mesej sumbangan yang diminta pemilik.

Penerimaan: tiada dakwaan localhost-only/no-public-deployment/no-public-Hall pada UI semasa; kiraan glosari konsisten; maklumat ketidakpastian kemasukan tidak ditukar menjadi kepastian.

Rujukan: [guides.js](../../public/js/guides.js), `about`; [home-guide.js](../../public/js/home-guide.js).

## Akaun privasi dan operasi sebelum pertumbuhan

1. **Pemulihan akaun penjaga/cross-device.** Anonymous identity bergantung pada pelayar. Eksport PDF/JSON bukan sistem recovery atau import cloud. Reka linking,authorization keluarga dan pemulihan sebelum membuat janji akses merentas peranti.
2. **Backup dan restore.** Tentukan backup/PITR mengikut keperluan,kekerapan,retention,RPO/RTO,akses admin dan drill restore. Jangan menganggap eksport peribadi sebagai backup cloud automatik.
3. **Retention dan deletion.** Tentukan tempoh simpanan bagi profil/attempt/feedback/Hall/counter. Counter mempunyai24-hour public read window tetapi tiada purge automatik; metadata private masih perlu polisi operasi.
4. **Kos dan scaling.** Semua attempts dibaca penuh dalam listRecords dan Dashboard dipanggil pada semua route. Gunakan pagination/cache/aggregate yang sesuai tanpa mencampurkan keluarga atau merosakkan denominator. Global traffic total document juga perlu pemantauan contention apabila trafik meningkat.
5. **Abuse controls.** Nilai App Check,quota/budget alerts,monitoring dan incident ownership. Cooldown per-Anonymous UID bukan perlindungan bot menyeluruh; counter bukan individu unik dan ranking bukan penilaian dipercayai.
6. **Dokumentasi semasa.** Banyak keputusan lama disimpan secara kronologi dengan supersession. Kemaskan pandangan current state agar tidak perlu meneka keputusan aktif; jangan mengubah original prompt byte-for-byte atau membuang skop pendidikan.

## Cara menyambung sesi akan datang

1. Baca [full_prompt.md](../../full_prompt.md), [Task.md](../../Task.md), laporan ini dan `AGENTS.md`.
2. Semak baseline semasa; jangan anggap semua dapatan masih belum dibaiki jika ada commit kemudian.
3. Mulakan A01/A02 dengan reproduksi dan acceptance di atas selepas pengguna meminta sambung kerja.
4. Untuk audit visual baharu,gunakan browser host apabila tersedia. Jika masih disekat,jangan akses sesi peribadi atau beralih kepada workaround tanpa authorization yang sesuai.
5. Simpan bukti ujian secara jujur,kemas kini docs selepas perubahan dan asingkan GitHub publication daripada Hosting deployment. Jangan menulis fixture kepada production untuk QA tanpa authorization khusus.
